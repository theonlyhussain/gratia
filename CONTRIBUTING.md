# Contributing to Gratia 🎵

First off, thank you for considering contributing to Gratia! It's people like you that make Gratia such a great local-first music player.

## Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). We expect all contributors to follow these guidelines to ensure a welcoming and inclusive environment for everyone.

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please create an issue! Be sure to include:
* Your device model and Android version
* Gratia version (found in Settings)
* Detailed steps to reproduce the issue
* What you expected to happen vs what actually happened
* Screenshots or screen recordings if applicable

### Suggesting Enhancements
Have an idea for a new feature? We'd love to hear it! When requesting features, please:
* Check if a similar feature request already exists.
* Explain *why* this feature would be useful, not just what it is.
* Describe how it fits into Gratia's design philosophy (clean, local-first, premium feel).

### Submitting Pull Requests
We welcome Pull Requests for bug fixes, performance improvements, and new features!
1. **Fork the repository** and create your branch from `main`.
2. **Discuss major changes**: If you are adding a large feature or changing the architecture, please open an Issue first to discuss it with the maintainers.
3. **Follow the Architecture**: Ensure your code follows the existing MVVM + Repository pattern.
4. **Design Philosophy**: Any UI changes should align with our Apple-inspired design principles (fluid motion, spring physics, dynamic colors, intuitive gestures). Check out the existing UI components before building new ones from scratch.
5. **Code Style**: We use standard Kotlin formatting. Ensure your code is clean and well-documented.
6. **Test**: Please test your changes thoroughly before submitting.

### Getting Started with the Code
1. Clone your fork: `git clone https://github.com/YOUR_USERNAME/gratia.git`
2. Open the project in Android Studio.
3. Let Gradle sync and download dependencies.
4. Build and run the app on an emulator or physical device.

## Community

If you have questions, feel free to open a Discussion on GitHub. We are always happy to help new contributors get started!
